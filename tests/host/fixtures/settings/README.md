# Historical settings upgrade fixtures

These `.nvs` files contain synthetic NVS key/value bytes, not complete flash/NVS
partition images. Each file records its original release tag and commit. They
were generated by compiling that commit's actual `app_settings.cpp` and headers
with `tests/host/settings_fixture_writer.cpp`, using fake NVS storage. Current
persisted structures are not used to manufacture old snapshots. Credentials and
keys are synthetic and never copied from a device.

Nine published tags, Beta-0.1 through Beta-0.4.3, each have CAN and Wi-Fi fixtures.
All six pages and four Victron configurations are populated. No 0.2.4 release is
claimed. Regenerate with `python tools/generate_settings_fixtures.py` after fetching
tags; use an ordinary little-endian host with g++ (the persisted ABI sizes are
asserted by historical code). Generator output is reviewed and committed, not
regenerated using the current writer during CI.

`settings_upgrade_test.cpp` loads each snapshot directly through current settings
code, verifies values and no unintended NVS writes, saves and reloads, and checks
failed commits, absent preference keys, arbitrary old padding, truncated groups,
future schemas and NVS initialization errors. Existing `settings_test.cpp` covers
schema-2 Wi-Fi migration, missing legacy passwords and migration retry.

Scope: application key/value compatibility. These tests do not run the real
ESP-IDF NVS filesystem, transport startup, UI, USB flashing, OTA selection or
bootloader. Source-specific depth/selection storage is covered by the separate
source tests, not these fixtures. Hardware acceptance must include a backed-up
configured older device, an application-only update, unchanged configuration and
stable startup. The Beta-0.4.3 application-only boot failure remains undiagnosed.

If NVS initialization fails, settings are preserved and init returns false. A
pending OTA trial fails existing startup-health checks; an ordinary boot has no
guaranteed automatic rollback. This change adds no recovery screen, updater or
partition-layout changes. Recovery requiring an erase must be explicit.
